# Crash Test Agents — Reusable UI Component Library (Tier-0)

Standalone HTML/CSS/SVG that renders the faked app UIs the Episode 1 screenplay
reuses across shots. **No paid AI generation, no external services** — every file
opens directly in a browser and is finished at **1920×1080, dark mode**.

All components import a single shared stylesheet, [`tokens.css`](./tokens.css),
generated from `production/branding/brand-system.md` (§1a tokens, §2 type, §4 motion).
Every color/type value is a `var(--…)`, so a later brand-hue tweak is a **one-line
change in `tokens.css`** and cascades to all seven components.

Fonts load from Google Fonts (all SIL OFL / free): **Space Grotesk** (display),
**Inter** (UI/body), **JetBrains Mono** (code/mono), each with a system-font
fallback baked into the `--font-*` tokens.

Motion is CSS `@keyframes` wherever possible (email feed ticking, counter spinning,
meter climbing, prompt sections appearing, wires drawing) so a screen-record is
**deterministic** — the same frames every capture. `prefers-reduced-motion` is
honored (montage renders can ignore it; see capture notes).

## Components

### 1. `sift-dashboard.html` — Sift inbox-triage (healthy)
Shots: **S001**, reused clean in **S049**.
The calm, trustworthy triage app: live feed of email cards, colored label pills
(`--label-sales/support/billing/urgent`) snapping on, green ✓ per row, a "Live ·
classifying" status pill, left label counts, right run-summary panel.
- **State:** `.stage[data-state="healthy"]`. The failure state is a separate file
  (see #2) but shares the `.card` / `.label` / `.check` classes so one stylesheet
  drives both.
- **Params:** none required — self-contained. Edit the `.card` list to reseed rows.
- **Motion:** cards rise+fade in staggered (`--dur-base`/`--ease-out`), label pills
  scale-snap (`--ease-snap`), checks draw their stroke. Loops once then holds.

### 2. `sift-failure.html` — Sift inbox-triage (FAILURE)
Shots: **S002** (cold-open break), escalated in **S034**.
Same dashboard broken: one malformed inbound card (glitching body), a
duplicate-send stack firing the same reply at Dana Okafor ×4, a **spinning
outbound counter** (rolling mono digit reel), and a **red API error stack**
(400s + missing loop guard).
- **State:** `.stage[data-state="failing"]`.
- **Motion:** counter reel rolls on `--ease-mech` (infinite), sent-cards slam in on
  a stagger, error lines reveal sequentially, status spinner stutters "mid-spin".

### 3. `harbor-inbox.html` — Harbor Supply Co. inbox
Shots: **S008**, **S013**, **S019**, **S030**.
~200-unread fictional support inbox for `support@harborsupply.co`. Invented senders
incl. the script's **Dana Okafor**, **priya@vendorline.co**,
**deals@free-cruise-now.biz**, plus spam/urgent flags. Bottom **"Everything here is
invented"** hazard-striped watermark strip.
- **Params:** none. Rows are generated by a **seeded PRNG (mulberry32, seed
  20260809)** from an invented sender table — identical every render, no network.
  Change `TOTAL` (default 200) or the `senders`/`times` arrays in the inline script.
- **Motion:** the list slow-scrolls (`scrolldemo`, alternating) to show volume;
  top/bottom edges fade so it reads as endless.

### 4. `round-slate.html` — ROUND 1..5 title slate (parameterizable)
Shots: **S003, S012, S023, S030, S032, S035, S039, S047** (+ concept slates).
Full-frame `--bg-deep` slate: faint reticle watermark, hazard-stripe rules top &
bottom (title-safe), kicker `ROUND 0X`, big display title, optional sub, reticle
mark bottom-right. Slam-in motion (`--ease-snap`).
- **Params (precedence: URL hash > query > `data-*` attr):**
  - `round` — number (rendered zero-padded, e.g. `2` → `ROUND 02`)
  - `title` — the round name (`+`/`%20` for spaces)
  - `sub` — optional secondary line
  - `variant` — `round` (default) or `concept` (single hero line, hides kicker)
  - `accent` — a word within the title to color-highlight
  - `tone` — `accent` (cyan, default) or `danger` (red) for the accented word
- **Examples:**
  - `round-slate.html#round=2&title=Dead+APIs&sub=fragile+chains`
  - `round-slate.html#variant=concept&title=failure+%3D+data&accent=data`
  - `round-slate.html#variant=concept&title=guardrails`
  - `round-slate.html#round=5&title=Secrets+%26+permissions&accent=Secrets&tone=danger`

### 5. `token-cost-meter.html` — token meter + running $ (with permanent disclaimer)
Shots: **S006** (ticking), **S037** (spiking), **S038** (dropping).
Segmented token meter climbing beside a rolling dollar figure and a wallet glyph.
Carries the **permanent, non-removable disclaimer strip**
("Illustrative — not a measured cost. Token & dollar figures are fabricated demo
values.") per the two ⚠️VERIFY flags — it's a fixed layout row, styled
`--warning`, that no state can hide.
- **State (`.stage[data-state]` or `#state=` hash):**
  - `ticking` — gentle climb, cyan fill (S006)
  - `spiking` — hard fast climb ~94%, **red** fill + red figures (S037)
  - `dropping` — falls from full to lean, **green** fill + "context quality ▲"
    indicator (S038)
- **Motion:** meter width transitions per state; JS rolls token/$ counters in 6
  mechanical steps to match `--ease-mech`. Numbers are deliberately stylized.

### 6. `system-prompt-builder.html` — system prompt filling in section by section
Shots: **S012, S014, S015** (+ referenced across S016/S018/S033/S040).
A markdown editor (`sift/system-prompt.md`) whose sections —
**Role · Context · Tools · Rules · Examples · Final notes** — appear on a timeline,
while a right sidebar checklist ticks each box **green** in sync. Line-number gutter
auto-built to match rendered lines.
- **Params:** none — the reveal is a fixed timeline (section delays `.6s…5.6s`).
  To render the S014 "all-unchecked / empty" beat, remove the `.sec` reveal delays
  (or set the doc body to the blank placeholder) — the checklist markup is reused.
- **Motion:** section blocks fade+rise (`secin`), checklist boxes draw+pop
  (`--ease-snap`) and rows light green; caret blinks on `--ease-mech` feel.

### 7. `flow-diagram.html` — Read→Classify→Label→Rolodash→Draft flow
Shots: **S009** (build), **S010** (desaturate), **S011** (rule vs needs-AI payoff);
the node kit also underpins S019/S022/S027/S028/S046.
Five connected nodes with glyphs + a Rolodash **CRM definition callout**. Each node
is **taggable**: `.tag-rule` (gray/desaturated, "rule" chip) or `.tag-ai`
(accent border + `--ai-glow` pulse, "needs AI" chip). Ships in the S011 payoff:
four gray rule nodes + one glowing `Classify` node. Legend + "Boring is reliable"
caption.
- **State:** `.stage[data-state="chunked"]` (default). For the plain S009 build,
  drop the `tag-rule`/`tag-ai` classes so nodes render neutral while wires draw.
- **To retag** any node: swap its class between `tag-rule` and `tag-ai` and update
  the `.chip` text. Wires draw left→right on a stagger.

## Toggling states quickly

Two patterns are used so states are screen-record-friendly without editing markup:

- **`data-state` attribute** on `.stage` (sift-dashboard, sift-failure,
  token-cost-meter, flow-diagram). Change it in devtools or via the URL hash where
  wired (`token-cost-meter.html#state=spiking`).
- **URL hash / query params** for `round-slate.html` (fully parameterized) and
  `token-cost-meter.html#state=`.

The `[data-theme="light"]` block in `tokens.css` exists for the S050 checklist
one-pager and light diagram exports; components default to `dark`.

## How to screen-record a component (headless capture)

These are **standalone local HTML files** — record them by pointing a headless
browser at a `file://` URL (or a tiny local server) at exactly 1920×1080. Nothing
below is installed by this task; these are the recommended commands to run on a
render box.

### Option A — Playwright screencast (recommended, deterministic)
Playwright records a WebM while the CSS animation plays. Run from any machine with
Node:

```bash
npm i -D playwright && npx playwright install chromium
```

```js
// capture.mjs — node capture.mjs sift-failure.html out/sift-failure.webm
import { chromium } from 'playwright';
const [ , , file, out ] = process.argv;
const b = await chromium.launch();
const ctx = await b.newContext({
  viewport: { width: 1920, height: 1080 },
  deviceScaleFactor: 1,
  recordVideo: { dir: 'out/', size: { width: 1920, height: 1080 } },
  reducedMotion: 'no-preference',          // let the keyframes play
});
const p = await ctx.newPage();
await p.goto('file://' + process.cwd() + '/' + file);
await p.waitForTimeout(6000);              // long enough for the animation beat
await ctx.close(); await b.close();        // video is finalized on context close
```

- Pass a hash for parameterized files, e.g.
  `file://…/round-slate.html#round=2&title=Dead+APIs`.
- WebM → MP4/ProRes for the editor: `ffmpeg -i out/xxx.webm -c:v prores_ks out.mov`.

### Option B — deterministic frame-by-frame (best for the edit)
For frame-accurate capture, drive the clock instead of wall time using
`puppeteer-screen-recorder`, or capture PNG frames while stepping
`page.evaluate` over the animation timeline, then assemble with ffmpeg at 30fps:

```bash
ffmpeg -framerate 30 -i frames/%04d.png -c:v prores_ks -pix_fmt yuv422p10le out.mov
```

### Option C — quick still (thumbnails / keyframe seeds)
```bash
npx playwright screenshot --viewport-size=1920,1080 \
  "file://$PWD/token-cost-meter.html#state=spiking" out/meter-spike.png
```

**Notes for the render box**
- Use `deviceScaleFactor: 1` so pixels map 1:1 to the 1920×1080 canvas.
- The `.stage` is a fixed 1920×1080 box centered on `--bg-deep`; a 1920×1080
  viewport sees it edge-to-edge.
- Animations mostly play once and hold, so start recording at page load and stop
  after ~6s (looping states — the failure counter, the AI-glow pulse, the inbox
  scroll — run continuously; trim in the edit).
- `reducedMotion: 'no-preference'` in the capture context overrides the
  `prefers-reduced-motion` guard so montage renders always animate.

## What is NOT in this library (and why)

These recurring/secondary elements from the screenplay were **out of scope** for
this task's seven-file build. Listed so the next pass can pick them up:

- **Rolodash CRM / order record / permissions** (S019/S023/S024/S031/S033/S042/S043)
  — key-status badge (active/expired), "no shipment logged" record, all-ON↔scoped
  permissions panel. Referenced by the flow diagram's Rolodash node but the panels
  themselves aren't built here.
- **Workflow error-handler / branch node kit** (S025–S028, S044, S046) — the
  flow-diagram node primitives cover the linear pipeline; the error-trigger handler,
  success/error branch split, and retry loop are not yet assembled as components.
- **Checklist sidebar / Agent Pre-Launch Checklist one-pager** (S022/S029/S050) —
  the prompt-builder ships a section checklist, but the standalone rules sidebar and
  the light-theme one-page render of `agent-prelaunch-checklist.md` are separate.
- **HTTP status chart** (S020/S021), **.env/.gitignore/file-tree editor** (S040/S041),
  **error-log sheet + device notification card** (S026/S041), **approval card**
  (S045) — secondary reusables, not in the requested seven.
- **Title/CTA/end cards** (S003 full title, S051/S052) — the round-slate covers
  round + concept slates; the full channel title card and the end/CTA cards (with
  the permanent synthetic-media disclosure line) are a related but distinct build.

The three **AI-b-roll analogy overlays** (soup S017, puppy S035, valet key S043)
are intentionally excluded — they are the only optional paid-generation assets and
each has a Tier-0 fallback per the screenplay.
