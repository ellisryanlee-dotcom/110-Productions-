# Prove a dashboard with an artifact before building a custom one

**What:** Once an agent has live connections, you can spin up quick interactive
"artifact" dashboards (in the desktop app's co-work area) that pull real data from a
connected source on open — e.g., a revenue/expenses view or a task-status view — in a
few minutes, before investing in a bespoke dashboard.

**Why it matters:** It embodies a proof-of-concept-first mindset: build the cheapest
thing that proves whether you'll actually use the view. If you never open the quick
artifact, you just saved yourself from building a full custom dashboard; if you check
it constantly, you've justified investing in one.

**The moves:**
1. Start a new artifact and tell the agent what you want to see and which connectors
   to pull from.
2. Let it generate a lightweight dashboard that fetches live data on open.
3. Use it for a while and observe how often you actually look at it.
4. Only if it proves valuable, build a custom dashboard (which needs a real data-sync
   and refresh cadence via a routine or scheduling platform).
5. Alternatively, skip standing dashboards and just ask the assistant for on-demand
   reports from multiple sources when you need them.

**Watch out for:** Artifact dashboards are quick but not perfect; a real always-fresh
dashboard requires syncing data and a refresh schedule — meaningfully more work.
Don't over-invest before the concept is proven. On-demand reports often beat
maintaining a dashboard you rarely open.
