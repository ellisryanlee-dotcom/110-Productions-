# The five levels of an AI second brain

**What:** A ladder of increasingly sophisticated ways to organize a personal/business
knowledge base for an AI, each answering a different retrieval question:
1. **Keyword + routing** — find a file/info by an exact word or name.
2. **Topic wiki** — pull everything on a topic together via indexes and backlinks.
3. **Semantic search** — retrieve by meaning, not exact wording.
4. **Knowledge graph** — trace typed relationship chains between entities.
5. **Always-on OS** — autonomous, continuously syncing/refreshing memory.

**Why it matters:** Higher is not automatically better. Each level solves a specific
pain; the goal is the lowest level that meets your needs. Adding complexity without a
real pain point just creates maintenance burden.

**The moves:**
1. Diagnose your actual pain: re-explaining things / exact-word lookups → level 1; many
   notes you forget → level 2; searches missing notes you know exist → level 3; needing
   relationship chains → level 4; running many offline agents on huge data → level 5.
2. Mix levels per folder — one part of the project can be plain markdown while another is
   a vector store or a graph.
3. Start simple and only climb when a concrete problem forces you to.

**Watch out for:** Chasing the fanciest level (or a pretty graph visualization) without
a pain point wastes effort and money. Level 5's always-on ingestion risks over-stuffing
context and doing more harm than good.

**Original example to invent:** Source mapped these to his own content business. Writers
should illustrate the five levels for a different person's knowledge base.
