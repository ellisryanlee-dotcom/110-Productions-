# Comparing agent harnesses: desk driver vs. on-the-go assistant

**What:** A practitioner's mental model for when to use different agent tools. A
terminal-based coding agent is the "daily driver" you sit and drive for knowledge work
and coding. Open-source personal agents (the source compares two such projects) are
the on-the-go option: you spin up crons and manage things from your phone, and they
wake and respond instantly. Because they all operate over a file/folder repo, you can
point several of them (including other coding agents) at the same GitHub repo of your
knowledge and skills.

**Why it matters:** These tools aren't mutually exclusive — they fill different roles.
Knowing which to reach for (desk deep-work vs. mobile quick-tasks) and that they share
a common repo substrate lets you mix them without lock-in.

**The moves:**
1. Use a terminal coding agent when seated for coding/knowledge work.
2. Use a lightweight personal agent (via messaging) for on-the-go, quick, scheduled
   tasks.
3. Keep your knowledge/skills in a GitHub repo so any harness can sit on top of it.
4. Expect minor terminology differences (e.g., instruction-file naming) and let the
   agent adapt the repo to the tool.
5. Pick based on where you are and the risk level, not brand loyalty.

**Watch out for:** This landscape shifts fast and choices are experience-based/asserted,
not benchmarked. Some personal-agent projects push frequent updates that can break your
instance; weigh stability. The durable asset is your repo, not any single tool.

**Original example to invent:** Source contrasted its own use of a coding agent vs.
two personal-agent projects. Writers should compare a different set of tools by role,
in their own words.
