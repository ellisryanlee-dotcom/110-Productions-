# The AI-driven SDLC and the specification bottleneck

**What:** The software development life cycle (SDLC) is the whole path from idea to production — requirements, design, implementation, testing, review, deployment, maintenance — not just writing code. AI coding assistants have collapsed the implementation phase from weeks to minutes/hours, because agents iterate against their own tests. But the front (requirements/specification) and back (validation) are still human-driven and haven't sped up much. So specification quality becomes the new bottleneck.

**Why it matters:** It explains why AI can 10x an engineer's code output without 10xing the business's output — the gains are bottlenecked by the parts around coding. Where you invest effort (writing sharp specs, building validation) now matters more than raw coding speed.

**The moves:**
1. Recognize implementation is no longer the constraint; requirements and validation are.
2. Invest in tighter specifications up front — they now bound overall throughput.
3. Strengthen validation at the end where humans still must judge quality.
4. Still remove implementation as a bottleneck where you can; it saves real time.

**Watch out for:** Faster code generation creates a false sense of overall speed if specs are vague and validation is weak. The middle being cheap tempts teams to skimp on the ends that now dominate.
