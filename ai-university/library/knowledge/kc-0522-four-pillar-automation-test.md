# The four-pillar test for what's worth automating

**What:** A quick screen for deciding whether a process is worth automating, based on four properties: **repetitive**, **time-consuming**, **error-prone**, and **scalable**. If a process doesn't hit at least two of the four, it's probably not worth automating yet; the best candidates hit all four.

**Why it matters:** Beginners automate whatever's in front of them and waste effort on low-value flows. A simple threshold keeps you focused on automations that actually save serious time or reduce real errors — the ones that produce ROI.

**The moves:**
1. Score a candidate process against the four pillars.
2. Require at least two hits before building; deprioritize anything that scores lower.
3. Favor processes that hit all four — those compound in value.
4. Combine with an events-not-on-demand bias (automate things that run without you) for maximum leverage.

**Watch out for:** A process can be genuinely useful to *you* but still be a poor automation target if it isn't repetitive/scalable — e.g., an assistant that only acts when you prompt it creates little leverage.

**Original example to invent:** The source contrasts an on-demand personal assistant with an event-triggered workflow. Writers should invent two different candidate processes and score each against the four pillars to show the cutoff.
