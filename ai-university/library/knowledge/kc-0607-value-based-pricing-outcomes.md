# Price on the outcome, not on your hours

**What:** Value-based pricing sets the fee by the value the system creates for the
client, not by the time it took you to build it. A build that took a couple of hours
can be worth far more than an hourly rate would suggest, because the client is buying
the result — saved time, recovered revenue, fewer errors — over its lifetime, not
your labor.

**Why it matters:** Hourly pricing punishes you for being fast and caps your upside.
Outcome pricing lets a genuinely valuable, quick-to-build system command a price that
still feels like a bargain to the client because it's a fraction of the value
delivered.

**The moves:**
1. Learn how the client does the task manually today and how long it takes them or
   their staff.
2. Estimate what an hour of that person's (or their employees') time is worth.
3. Add intangible benefits (consistency, fewer mistakes, freed focus).
4. Convert all of that into a value figure, then price a comfortable fraction of it.
5. Present the price against that value so it reads as an obvious win, not a cost.

**Watch out for:** You must actually understand the client's specific numbers — a
generic price with no value story invites objections. Don't anchor the conversation
on nodes, API calls, or build hours; the buyer doesn't care about those.

**Original example to invent:** Source referenced a content-generation build sold for
a flat fee. Writers should construct a different scenario and walk the value math end
to end with invented but realistic numbers.
