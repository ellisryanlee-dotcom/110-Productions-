# The AI Operating System and the Four C's

**What:** An "AI operating system" is a coding-agent project that becomes the layer
you work through all day — it can see your files and communications, act on them, and
remember them better than you. It's built in four ordered pillars, the Four C's:
Context (what it knows about you, your team, tools, voice, money), Connections (what
data it can reach), Capabilities (what it can actually produce/do), and Cadence
(when it acts on its own while your laptop is closed).

**Why it matters:** It reframes AI from a chat window into a durable, tool-agnostic
personal operating layer. The order matters — each C builds on the previous: no
capability without context, no cadence without connections. It also survives tool
churn because the foundation (files, structure, principles) ports across harnesses.

**The moves:**
1. Context: load who you are, your business, priorities, and communication style.
2. Connections: wire the tools where your real data lives (tasks, calendar, comms,
   revenue, meetings, knowledge).
3. Capabilities: build skills/SOPs so it can produce work, not just answer.
4. Cadence: schedule skills/automations so it runs in the background.
5. Test each pillar with a concrete probe (e.g., "plan my day," "build the Q3 report").

**Watch out for:** Skipping the order leaves gaps (a connected agent with no
capabilities is just a search box). Tools change roughly every six months — invest in
the durable layer underneath, not any one product. A quick test: open a fresh session
and ask a question; if it answers like a stranger, your context pillar is thin.

**Original example to invent:** Source built the OS around a creator/education
business. Writers should instantiate the Four C's for a different business type.
