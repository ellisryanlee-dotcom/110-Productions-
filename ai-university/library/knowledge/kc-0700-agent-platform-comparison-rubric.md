# A rubric for comparing agent-building platforms

**What:** A repeatable set of categories for judging any visual agent/automation
builder against another, instead of reacting to hype. The six categories are:
ease of use (barrier to entry for a non-coder), triggers (how a run can be
started), agent tools (breadth of actions/integrations), model support (which
LLMs you can use), UI/chat components (how you expose the agent to end users),
and deployment & control (where it runs and who owns the data). Score each
platform per category and total.

**Why it matters:** New "X just killed Y" narratives appear constantly. A fixed
rubric lets you cut through marketing and match a tool to a specific user and
use case rather than declaring one universal winner. The same platform can win
or lose depending on whose needs you score for.

**The moves:**
1. Fix your categories before you open either tool, so the comparison stays fair.
2. For each category, do the *same* concrete task in both tools and note the
   friction (steps, API keys, unclear options).
3. Score each category on a common scale and total them.
4. State explicitly which persona you scored for (beginner vs developer,
   consumer vs agency) and note how the winner would flip for another persona.

**Watch out for:** A single total score hides that the "loser" may be ideal for
a different buyer. Also weight categories by what the buyer actually cares about;
an even weighting can mislead.

**Original example to invent:** The source compared two named agent builders on
these axes. Writers should run the rubric on a *different* pair of tools (or a
different domain entirely, e.g., two scraping tools) and build their own scoring
table.
