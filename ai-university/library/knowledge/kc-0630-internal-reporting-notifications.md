# Internal reporting and status notifications that run themselves

**What:** An automation that gathers information people currently compile by hand —
pipeline numbers, client KPIs, cross-tool status — pulls it from the source systems on
a schedule, runs the analysis, and delivers it where the team already looks: a daily
chat message, a weekly email, or an event-triggered alert when a deal hits a stage or
a project slips. No new dashboard, tool, or process for anyone to learn.

**Why it matters:** Compiling reports is easy but manual and repetitive, eating hours
every week. Automating it frees that time for higher-value work and, once a team
relies on it, becomes extremely sticky — they can't imagine going back. Delivering
into existing tools ("meet them where they already work") means zero habit change,
which is what makes it adopted and profitable.

**The moves:**
1. Identify the recurring compile-and-distribute task and its source systems.
2. Pull real-time data, run the needed analysis.
3. Push the output into the channel the team already checks (chat, email, existing UI).
4. Add event-triggered alerts for thresholds and exceptions.

**Watch out for:** The value is in fitting existing habits — introducing a shiny new
dashboard people must learn undercuts adoption. Position it as freeing a person for
higher-leverage work, not replacing them, to ease buy-in.

**Original example to invent:** Source cited a simple job that reformatted daily phone
orders for a construction crew. Writers should invent a different reporting automation
and show it delivered into a tool the team already uses.
