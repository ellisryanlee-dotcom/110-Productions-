# Agentic workflows: describe the destination, not the route

**What:** A shift in how automations are built. In drag-and-drop platforms you specify how — placing nodes, wiring variables, configuring API calls, debugging errors. In agentic building you specify what — where data comes from, what should happen, where it ends up — in natural language, and the agent handles the implementation, writes the code, and fixes its own errors.

**Why it matters:** The ceiling on traditional automation was never what the systems could do; it was how long it took to build them by hand. Describing outcomes collapses builds that took a day into minutes.

**The moves:**
1. State the source of the data, the transformation needed, and the destination — in plain language.
2. Let the agent choose the implementation, write the code, and connect the tools.
3. Focus your effort on clearly describing the desired outcome rather than on wiring.
4. Direct it the way you'd brief a capable developer: describe the problem and outcome, then answer its questions.

**Watch out for:** What you build isn't fundamentally different from before — it's how you build it that changed. You still must know what a good outcome looks like to describe it well and to catch mistakes.
