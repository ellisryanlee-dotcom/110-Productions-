# ROI / value-based pricing for automation projects

**What:** Price an automation by the value it creates for the client, not by how
long it takes you to build. You quantify the time or money a process currently
costs, translate that into monthly and annual savings, and set a price the client
can see is a fraction of the return — so the purchase reads as an investment with a
measurable payback, not an expense.

**Why it matters:** Beginners pick random numbers or price by technical effort,
which leaves money on the table and invites hourly-freelancer comparisons. Anchor
to ROI and clients stop haggling on cost and start thinking about return.

**The moves:**
1. In discovery, measure the current cost of the process (hours/week or dollars).
2. Multiply hours saved × hourly rate × ~4 weeks for monthly savings, then × 12
   for annual savings; also weigh opportunity cost of the freed time.
3. Set the price well below that annual value so payback is obviously fast.
4. Present it in black-and-white as an investment with a measurable return.

**Watch out for:** Clients don't care whether a build took you 2 hours or 20 — only
the outcome. Some value (e.g., a general assistant's scattered admin savings) is
harder to tie to ROI than others (e.g., outreach/sales) — acknowledge that and lean
on value framing where the cadence is clear.

Writers should build an ROI case for a different automation with invented numbers.
