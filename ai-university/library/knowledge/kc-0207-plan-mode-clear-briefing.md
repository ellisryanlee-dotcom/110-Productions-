# Use plan mode and brief clearly before building

**What:** Before letting a coding agent build something, switch it into a planning
mode where it reasons harder, inspects the whole project, and interrogates you with
questions before writing anything. You provide a detailed brief — the goal *and* the
specific features/outputs you want — and answer its follow-ups; it then produces a
plan and a to-do list you approve.

**Why it matters:** Vague instructions plus full autonomy yield poor output. Planning
first surfaces requirements you hadn't considered, gives the agent a strong
understanding of intent, and turns a big build into a tracked checklist you can watch
without micromanaging. Clarity up front dramatically improves the first result.

**The moves:**
1. Enter plan mode when creating anything non-trivial.
2. Brain-dump the objective, desired features, and the concrete deliverable.
3. Ask it to research options (APIs, MCP, skills) it should consider.
4. Answer its clarifying questions; let it refine the plan.
5. Approve the plan; it maintains a to-do list and knocks items off one by one.

**Watch out for:** The more precisely you specify up front, the less back-and-forth
later — but it is never perfect, so expect to iterate. A to-do list also lets you
step away and check progress rather than supervising every action.
