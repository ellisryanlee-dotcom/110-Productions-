# The Three M's of AI: mindset, method, machine

**What:** A high-level model for adopting AI productively. Mindset is the lens you
bring; Method is how you decide what's worth automating and how much; Machine is the
technical build. The mindset layer carries three habits: the default shift (before
any task, ask how AI could do at least part of it), the function breakdown (your role
is a tree of small tasks — automate one chunk at a time), and the curiosity rule
(question the reasoning behind every answer instead of just taking it — approach AI as a teacher to learn from, not a dispenser that hands you finished output).

**Why it matters:** Most people ask a binary question — "will AI do this for me?" —
and give up when the answer is "not fully." Asking instead "what share of this could AI carry — 30%? 60%?" finds value in
nearly every task. Breaking work into
reusable chunks makes big, vague automations feel achievable and lets pieces be
recombined across processes.

**The moves:**
1. Default shift: for every recurring/boring task, first brainstorm how to automate
   part of it rather than doing it manually.
2. Function breakdown: decompose a role into tasks, then tasks into reusable chunks;
   automate the easiest high-leverage chunk first.
3. Curiosity rule: interrogate outputs ("why this design?", "what if input X?") so
   you're not shipping code you don't understand.
4. Treat leverage as a percentage to maximize, not a yes/no.

**Watch out for:** This is asserted framing, not a measured result. The point isn't
100% automation — capturing even 30–75% of a task is a real gain. Don't skip the
curiosity habit; blindly trusting generated code ("dark code") is how systems break
in ways you can't diagnose.

chunks. Writers should decompose a different role/workflow to show the habit.
