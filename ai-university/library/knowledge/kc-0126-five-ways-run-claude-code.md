# Five ways to run Claude Code (and how to pick one)

**What:** The same agentic coding engine can be run five ways: (1) the terminal/CLI — the foundational surface every other wraps; (2) a desktop app — a visual GUI with panels, previews, and native scheduled tasks; (3) the web — a browser/cloud service tied to a repo that keeps running with your machine off; (4) inside an IDE via an extension (VS Code, and similar editors) — files and agent side by side; (5) on a VPS — an always-on remote server next to your infrastructure.

**Why it matters:** Each trades power for approachability. Knowing the differences lets you match the surface to your comfort and workload rather than fighting the tool.

**The moves:**
1. Terminal: most control and earliest features; text-only, steeper learning curve — for people who live in a shell.
2. Desktop app: least intimidating, visual diffs, app preview, parallel isolated sessions — good starting point.
3. Web: near-zero setup, runs on the cloud, sessions persist while you're away — good for long tasks or working from a phone/tablet.
4. IDE extension: install the extension, sign in with a paid plan, open a folder as your project; see files/plans while the agent works; drop to the terminal for CLI-only commands.
5. VPS: always-on, SSH in from anywhere, sits next to databases/containers; needs basic server know-how.

**Watch out for:** You need a paid plan (free tier excludes the tool). Some CLI-only commands (e.g., managing agents) won't run in an IDE panel — open the terminal instead. On a server, be careful with permissions since the agent can see everything there.
