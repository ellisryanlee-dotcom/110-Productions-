# Coding sidekick vs. always-on assistant: two different tools

**What:** Two categories of agent tooling get conflated. A coding assistant (e.g.,
Claude Code) lives in your dev environment and helps you read, write, and fix code on
your local machine. An always-on assistant framework (the tool once called Clawdbot,
later renamed Moltbot) runs 24/7 on your own hardware or a server, holds persistent
memory, is talked to through a chat channel, and is designed for broad system access.
A useful way to compare them is across concrete axes: out-of-the-box ability, setup
friction/risk, cost, power/access, security, everyday usability, proven ROI, and who
it's really for.

**Why it matters:** They feel similar and both were riding hype, but they trade off
differently. Choosing well means scoring the axes *you* care about rather than
following what's trending. Notably, much of what the always-on tool does can also be
built inside a coding assistant you already understand.

**The moves:**
1. Score each tool on the axes that matter to your use case, not a generic verdict.
2. Weight proven ROI and security higher if this is going into real work.
3. Recognize the always-on tool feels more powerful and proactive out of the box,
   while the coding assistant is more understood, lower-risk, and battle-tested.
4. Ask whether you could just build the desired behavior inside the tool you already
   know before adopting a new, riskier one.

**Watch out for:** Hype distorts judgment — ask why something is trending and what the
creators' incentives are. A tool being new and exciting is not the same as it being
ready for your business. Names and scores change fast; the axes are the durable part.

**Original example to invent:** Source ran a head-to-head scoring rubric. Writers
should build their own comparison around a different decision and invent the axis
scores rather than reusing the source's numbers.
