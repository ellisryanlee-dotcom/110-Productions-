# Servicing a client end-to-end (plan → build → review → deploy → handover)

**What:** A repeatable delivery process for a first AI project (illustrated with an outward-facing website chatbot that nurtures leads, captures contact info, pushes to a conversion event, and answers questions from a knowledge base). The phases are: identify the client's needs and the value the solution provides; gather requirements; plan; build; review; deploy; and hand over.

**Why it matters:** A clear pipeline lets a beginner deliver reliably and, crucially, scale communication. Batching feedback and handing ownership to the client are what make the work maintainable as you take on more clients.

**The moves:**
1. Identify needs and articulate the concrete value (e.g., lead nurture, lead capture, conversion, support).
2. Collect requirements from the client (knowledge-base Q&A content, desired conversation flow, what to capture, the conversion target).
3. Plan the conversation flow visually (a diagramming tool) and get the client to validate it before building.
4. Build on a no-code base plus supplementary services via API for stronger knowledge-base answers.
5. Review by sending a test link; ask the client to stress-test and return one batched document of feedback — avoid endless back-and-forth by working in iteration batches.
6. Deploy by transferring the build to the client's own account (so billing sits with them) and giving them the embed snippet for their site.
7. Hand over; continue light tweaks as needed.

**Watch out for:** Constant one-off communication doesn't scale — insist on batched feedback rounds. Make sure billing/ownership moves to the client's account at deployment so costs aren't stuck on yours. For your first client, deliberately pick low-hanging fruit rather than an over-ambitious scope.
